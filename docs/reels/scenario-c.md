# 릴스 시나리오 C — "단톡방에 이게 왜 올라와?"

공유된 결과에서 시작해, 그 네모들이 어떻게 만들어졌는지 거꾸로 따라간다.
블로그에서 정한 "워들류는 지인끼리 공유로 경쟁한다"는 의도를 그대로 보여 주는 구성이다.

## 규격

- 1080×1920 세로, 30fps, 약 21초(630프레임). 사운드 없음. 자막이 내레이션을 대신한다.
- 편집: Remotion. 실제 화면은 Playwright로 로컬 앱을 폰 크기(390×844, 배율 3)로 띄워 대본대로 플레이하며 녹화한다.
- 디자인: 앱과 같은 평면 단색. `#3366CC`, `#F3F7FF`, Pretendard, 로고만 Rhodium Libre. 그라데이션·그림자·광택 없음.
- 자막 안전 영역: 위 220px, 아래 380px은 릴스 UI(계정명, 설명, 버튼)에 가리므로 핵심 글자를 두지 않는다.

## 연결 장치

- 1장면 마지막 친구의 네모 줄과 4장면에서 채워지는 네모 줄을 똑같이 맞춘다. 보는 사람이 "아, 그 네모가 이거였구나" 하고 알아채는 것이 영상의 핵심이다.
  그래서 녹화를 먼저 하고, 녹화에서 나온 실제 이모지·횟수·시간으로 1장면의 말풍선을 만든다.
- 2→3장면 전환: 확대된 첫 네모가 홈 화면의 출발 문서 칸으로 바뀐다.
- 5→6장면 전환: 공유 버튼을 누른 손가락 표시에서 말풍선이 튀어나간다.

## 메신저 화면

- 특정 메신저(카카오톡 등)를 흉내 내지 않는다. 노란색·말풍선 꼬리 모양·앱 아이콘을 따라 하지 않고 링클 색으로 그린 중립적인 대화방이다.
- 친구 셋은 동휘, 민서, 진우(이 순서로 올라온다). 프로필은 이름 첫 글자를 넣은 원.
- 말풍선 글자는 실제 공유 문구 형식을 그대로 쓴다.

```
Linkle #N 🔗
5번 1분 11초

🟥🟧⏪🟨🟦🏁

linkle.naco.im
```

## 녹화 준비

- 실제로 나간 오늘의 문제는 스포가 되므로, 로컬 D1에 영상용 문제(불고기 → 뉴발란스)를 넣고 그날의 문제로 띄운다.
- 녹화 대본(누를 링크 순서)은 미리 정해 두고 Playwright가 그대로 누른다. 되돌아가기 한 번을 일부러 넣는다.
- 이동 5~6번, 시간 1분대가 보기 좋다. 녹화는 실제 속도로 하고 배속은 Remotion에서 준다(시간 표시는 실제 기록 그대로).

## 정할 것

- 영상용 문제 조합(기본값: 불고기 → 뉴발란스)
- 친구 셋의 결과 숫자
- 길이 21초 유지 또는 15초로 줄이기(줄이면 2장면과 6장면을 뺀다)

## 만든 것 (2026-11-23, 첫 판)

`apps/reels`에 있다. 결과는 `apps/reels/out/linkle-reel-c.mp4`(1080×1920, 30fps, 무음). 첫 판은 23초, 둘째 판(같은 날 다듬음)은 34.8초다.

둘째 판에서 바꾼 것:

- 폰을 캔버스 폭의 74%(800px)로 키웠다. 폰 전체를 가운데 두되, 누를 단추(되돌아가기, 결과 공유)가 릴스 아래 글자 영역에 걸릴 때만 화면을 끌어올린다(`plan.ts`의 `CAMERA`).
- 녹화를 여유 있게 다시 찍고(멈춤 1.5~2배), 문서를 보는 동안은 1.1~1.4배속, 여는 동안만 0.4~0.5초로 줄였다. 처음 판은 2~2.5배속이었다.
- 첫 대화방이 비어 보이지 않게 앞서 오간 짧은 대화 넷(민서 "오늘 링클 나왔다" 등)을 깔았다.
- 녹화 결과는 5번 30초, 네모는 같다(`🟥🟧⏪🟧🏁`).

셋째 판에서 자막을 해요체로 바꾸고, 문제 내용(뉴발란스)을 자막에서 뺐다. 위 장면 표의 자막보다 이쪽이 최신이다.

| 장면 | 자막 |
|---|---|
| 1 | 요즘 단톡방에 이 네모가 자주 올라와요 |
| 2 | 이게 뭐냐면요 |
| 3 | 매일 그날의 문제를 하나씩 풀어요 |
| 4 | 위키피디아 문서 속 링크만 눌러서 / 목표 문서까지 가요(두 줄) → 목표에 가까울수록 색이 파래져요 → 길을 잘못 들면 ⏪ 되돌아가요 → 목표 문서에 닿을 때까지 이어 가요 |

넷째 판: 끝 화면을 4초 더 보여 주고(전체 38.8초), 끝 화면 묶음을 세로 가운데(960px)에 두고 간격을 맞췄다. 글꼴 스타일시트가 들어온 뒤에 찍도록 고쳤다(전에는 대체 글꼴로 찍힐 수 있었다).

친구들끼리 나누는 대화방 글("오늘 링클 나왔다", "30초?? 어떻게 감")은 친구 사이 말투라 반말로 둔다.

시나리오와 달라진 점:

- 4장면에서 채워지는 네모는 진우의 것이 아니라 **내 실제 결과**다. 6장면에서 내 결과를 올리는데, 진우와 똑같은 줄이면 어색해서다. 같은 형식의 네모가 만들어지는 과정으로 "아, 그거구나"를 준다.
- 실제로 녹화한 판: 불고기 → 서울특별시 → 롯데월드타워 → ⏪ → 서울 이랜드 FC → 뉴발란스, 5번 21초, `🟥🟧⏪🟧🏁`. 파란 네모가 나오지 않아 "목표와 가까워질수록 파랑" 대신 **"멀면 🟥 가까우면 🟦"**로 썼다.
- 친구 결과: 동휘 7번 2분 3초 `🟥🟨⏪🟧🟩🟦🏁`, 민서 4번 58초 `🟧🟨🟩🏁`, 진우 6번 1분 12초 `🟥🟧🟧⏪🟩🏁`. 진우의 답은 "21초?? 어떻게 감".
- 홈의 "지금까지 3명이 도착했어요"는 친구 셋에 맞췄다. 그래서 내 도착 순서는 4번째다.
- 1장면과 6장면의 자막은 말풍선을 가리지 않게 위(방 이름 자리)에 둔다. 도착 장면의 자막은 공유 버튼을 가리지 않게 가운데에 둔다.
- 연속 기록 축하 화면은 녹화되지만 영상에서는 잘라 낸다.

다시 만드는 순서:

1. `pnpm --filter reels setup` — 녹화 전용 DB(`apps/reels/.state`)를 만든다. 평소 개발용 DB와 따로다.
2. `.claude/launch.json`의 `reels-worker`(8821)와 `reels-web`(5211)을 띄운다.
   작업 트리에서 다른 기능을 고치는 중이라 서버가 뜨지 않으면, 마지막 커밋을 따로 꺼내(`git worktree add --detach .claude/worktrees/reels-rec HEAD`, 그 안에서 `pnpm install`, `mkdir -p apps/web/dist`) 거기서 띄우고, 1, 3단계에는 `REEL_WORKER=<그 체크아웃>/apps/worker`를 붙인다. 2026-11-23 녹화는 이렇게 했다.
3. `pnpm --filter reels record` — 앞선 판을 지우고 대본대로 플레이하며 녹화한다. `public/rec/play.mp4`와 `timeline.json`(탭 자리, 장면 시각, 공유 문구)이 나온다. 위키백과 문서가 바뀌어 링크 자리가 달라져도 대본은 링크 이름으로 찾는다.
4. `pnpm --filter reels studio`로 보며 고치고, `pnpm --filter reels render`로 뽑는다.

장면 시각과 배속은 `src/plan.ts`, 그림은 `src/Reel.tsx`와 `src/Chat.tsx`에 있다.
Remotion은 개인과 3명 이하 회사는 무료이고, 그보다 크면 회사 라이선스가 필요하다.
